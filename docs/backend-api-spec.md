# Backend API Specification — Constituency AI

## Overview

This document defines the REST API contract between the **Citizen Mobile App** (Expo/React Native) and the **FastAPI Backend**. All endpoints are versioned under `/api/v1/`.

**Base URL (dev):** `http://localhost:8000`
**Base URL (prod):** `https://api.constituency.ai`

**Auth:** Bearer JWT token in `Authorization: Bearer <token>` header (except auth endpoints).

**Format:** All requests/responses use JSON. File uploads use `multipart/form-data`.

---

## 1. Authentication

Supabase Auth–compatible flow using phone OTP.

### 1.1 Send OTP

```http
POST /api/v1/auth/send-otp
Content-Type: application/json

{
  "phone": "+919876543210"
}
```

**Response `200`:**

```json
{
  "success": true,
  "message": "OTP sent to +919876543210",
  "expires_in": 300
}
```

**Response `400`:**

```json
{
  "detail": "Invalid phone number format"
}
```

### 1.2 Verify OTP

```http
POST /api/v1/auth/verify-otp
Content-Type: application/json

{
  "phone": "+919876543210",
  "otp": "123456"
}
```

**Response `200`:**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 1800,
  "user": {
    "id": "uuid",
    "full_name": null,
    "phone": "+919876543210",
    "role": "citizen",
    "is_new_user": true
  }
}
```

**Note:** `is_new_user` flag allows the mobile app to redirect to profile setup on first login.

### 1.3 Refresh Token

```http
POST /api/v1/auth/refresh
Content-Type: application/json

{
  "refresh_token": "eyJhbGciOiJIUzI1NiIs..."
}
```

**Response `200`:**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 1800
}
```

## 3. Submissions (Complaints)

All submission endpoints require authentication.

### 3.1 Create Submission

```http
POST /api/v1/submissions
Authorization: Bearer <token>
Content-Type: multipart/form-data

category: "roads"
description: "Large pothole near MG Road junction causing accidents"
latitude: 12.9716
longitude: 77.5946
address: "MG Road, Bangalore"
images: <file1> <file2> <file3>  (max 3, optional)
document: <file>  (optional, single file)
voice: <file>  (optional)
```

Alternatively, if media is pre-uploaded:

```http
POST /api/v1/submissions
Authorization: Bearer <token>
Content-Type: application/json

{
  "category": "roads",
  "description": "Large pothole near MG Road junction causing accidents",
  "latitude": 12.9716,
  "longitude": 77.5946,
  "address": "MG Road, Bangalore",
  "image_urls": ["https://storage.example.com/uploads/uuid/img1.jpg"],
  "document_url": "https://storage.example.com/uploads/uuid/doc1.pdf",
  "voice_url": "https://storage.example.com/uploads/uuid/voice.mp3"
}
```

**Response `201`:**

```json
{
  "id": "uuid",
  "title": "Pothole on MG Road",
  "description": "Large pothole near MG Road junction causing accidents",
  "category": "roads",
  "status": "new",
  "location": {
    "latitude": 12.9716,
    "longitude": 77.5946,
    "name": "MG Road, Bangalore"
  },
  "image_urls": ["https://storage.example.com/uploads/uuid/img1.jpg"],
  "document_url": null,
  "voice_url": "https://storage.example.com/uploads/uuid/voice.mp3",
  "ai_summary": null,
  "created_at": "2025-06-15T10:30:00Z",
  "updated_at": "2025-06-15T10:30:00Z"
}
```

**Notes:**
- `title` is auto-generated by AI after creation. Returned as `null` initially.
- Submission immediately gets `status: "new"`, then transitions through the AI pipeline asynchronously via Celery.

### 3.2 List Submissions

```http
GET /api/v1/submissions?status=under_review&page=1&limit=20&sort=recent
Authorization: Bearer <token>
```

**Query Parameters:**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `status` | string | `all` | Filter: `all`, `new`, `ai_processing`, `analyzed`, `under_review`, `resolved`, `closed` |
| `page` | int | `1` | Page number (1-indexed) |
| `limit` | int | `20` | Items per page (max 50) |
| `sort` | string | `recent` | Sort: `recent`, `oldest`, `status` |

**Response `200`:**

```json
{
  "items": [
    {
      "id": "uuid",
      "title": "Pothole on MG Road",
      "category": "roads",

      "image_count": 2,

      "updated_at": "2025-06-15T11:00:00Z"
    }
  ],
  "total": 42,
  "page": 1,
  "limit": 20,
  "total_pages": 3
}
```

```http
PUT /api/v1/submissions/{id}/feedback
```

## 7. Error Responses

Consistent error format across all endpoints:

```json
{
  "detail": "Human-readable error message",
  "code": "VALIDATION_ERROR",
  "errors": [
    {
      "field": "description",
      "message": "Description must be at least 10 characters"
    }
  ]
}
```

**Standard error codes:**

| HTTP Status | Code | Meaning |
|-------------|------|---------|
| 400 | `VALIDATION_ERROR` | Invalid input |
| 401 | `UNAUTHORIZED` | Missing or invalid token |
| 403 | `FORBIDDEN` | Insufficient permissions |
| 404 | `NOT_FOUND` | Resource not found |
| 409 | `CONFLICT` | Duplicate or state conflict |
| 422 | `UNPROCESSABLE_ENTITY` | Request body validation failed |
| 429 | `RATE_LIMITED` | Too many requests |
| 500 | `INTERNAL_ERROR` | Server error |

## 8. Submission Status Flow

```
new → ai_processing → analyzed → under_review → resolved
                                         ↓
                                      closed
```

| Status | Meaning | Display Color |
|--------|---------|---------------|
| `new` | Received, awaiting AI pipeline | Grey |
| `ai_processing` | AI is analyzing (translation, classification, geotagging) | Blue (animated) |
| `analyzed` | AI analysis complete, awaiting human review | Blue |
| `under_review` | Being reviewed by constituency office | Amber/Yellow |
| `resolved` | Issue addressed/completed | Green |
| `closed` | Issue closed (duplicate, out of scope, or rejected) | Grey |

---

## 9. Rate Limiting

- **Auth endpoints:** 5 requests per minute per IP
- **Submission create:** 10 per hour per user
- **Upload endpoints:** 20 per hour per user
- **Read endpoints:** 60 per minute per user

Rate limit headers included in responses:

```
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 8
X-RateLimit-Reset: 1686830400
```

## 10. Data Model — Submission (Complaint) — Full Schema

```python
# SQLAlchemy model
class Complaint(Base):
    __tablename__ = "complaints"

    id: UUID                     # Primary key
    user_id: UUID                # FK → users.id
    title: str                   # AI-generated title (nullable initially)
    description: str             # Original user description (may be non-English)
    description_en: str | None   # English translation (populated by AI pipeline)
    original_language: str       # Detected language code (populated by AI)
    category: str                # roads, water, health, etc.
    status: str                  # See status flow above
    location: Point              # PostGIS POINT (SRID 4326)
    address: str | None          # Reverse-geocoded address
    ward: str | None             # Ward name/number (populated by AI geotagging)
    constituency_id: UUID | None # FK → constituencies table
    ai_summary: str | None       # AI-generated English summary
    ai_confidence: float | None  # 0.0–1.0 confidence score
    feedback_rating: str | None  # thumbs_up / thumbs_down
    feedback_comment: str | None
    image_urls: list[str]        # JSON array of S3 URLs
    document_url: str | None     # S3 URL
    voice_url: str | None        # S3 URL
    voice_transcript: str | None # Transcribed text (original language)
    is_deleted: bool             # Soft delete
    created_at: datetime
    updated_at: datetime
```

**New columns needed vs. current schema:**
- `description_en`
- `original_language`
- `ward`
- `constituency_id`
- `ai_summary`
- `ai_confidence`
- `feedback_rating`, `feedback_comment`
- `image_urls` (currently not in model)
- `document_url`, `voice_url`, `voice_transcript`
- `is_deleted`

## 11. Data Model — User (Profile) — Full Schema

```python
class User(Base):
    __tablename__ = "users"

    id: UUID
    phone: str                   # Unique, NOT NULL (primary identifier)
    email: str | None
    full_name: str | None
    avatar_url: str | None       # S3 URL
    preferred_language: str      # Default: "en"
    constituency_id: UUID | None # FK → constituencies
    notification_enabled: bool   # Default: true
    role: str                    # "citizen" | "mp" | "admin"
    is_verified: bool            # Phone verified via OTP
    created_at: datetime
    updated_at: datetime
```

**New columns needed vs. current schema:**
- `avatar_url`
- `notification_enabled`
- `phone` (currently nullable; should be NOT NULL primary identifier)
- `email` (currently NOT NULL; should be nullable for phone-first auth)
